# Torman

Приложение для Windows: PDF-каталог сохраняется на компьютере, Gemini подбирает товары по характеристикам. Готовый архив для передачи: `dist/Torman-Windows.zip`. Python получателю не нужен. Логотип используется в приложении, окне запуска, favicon и значке EXE.

Поддерживаются текстовые PDF и сканы до 20 МБ / 300 страниц, без пароля. Исходный документ сохраняется без изменений. Карточки подбора содержат физические номера страниц и ссылки на PDF. Старые каталоги и история предыдущих версий сохраняются до явной замены файла.

## Поиск и производительность

- При первом быстром подборе PDF распознаётся Gemini по 6 целевых страниц; по одной соседней странице добавляется для контекста таблиц. До 3 запросов выполняются параллельно.
- Проверенные части немедленно сохраняются в SQLite. Повторный запуск продолжает подготовку. Переполненные ответы автоматически разбиваются на меньшие части; частичный ответ не принимается как полный.
- Последующие запросы передают только компактные распознанные записи. Все записи участвуют в подборе: предварительного отсечения по ключевым словам нет. Большие каталоги проверяются параллельно, кандидаты затем сравниваются.
- В быстром подборе для моделей Gemini 3 Flash используется `thinkingLevel: low` и короткий структурированный ответ с ID. Значения характеристик берутся из сохранённых записей; неизвестные ID отклоняются.
- До 100 точных запросов кешируются на диске. Ключ включает каталог, модель, версию формата и сам запрос. Кешированный ответ отдаётся сразу из HTTP-обработчика, без очереди, повторного чтения PDF или Gemini; доступен без интернета и API-ключа.
- Смена PDF сбрасывает индекс и кеш. Для другой модели используется отдельный индекс. Завершившаяся старая задача не может записать индекс в новый каталог.
- Режим «Проверить по исходному PDF» всегда отправляет исходный PDF заново, обходя индекс и кеш. Он нужен для проверки сложных таблиц, общих свойств серий и связей между удалёнными страницами.
- Число распознанных записей не доказывает полноту извлечения. Нечитаемые страницы показываются пользователю; такие результаты не кешируются. Реальная скорость и качество зависят от PDF, Gemini, сети и квоты.
- Пустой список товаров в корректном ответе — обычный результат для нетоварного документа. Интерфейс предлагает загрузить каталог. При нарушении схемы программа один раз запрашивает исправленный ответ и повторно проверяет все поля, диапазоны страниц и противоречия характеристик. Повторная ошибка остаётся на экране с путём поля; исходные значения и ключ в диагностике не показываются.

## Запуск из исходников

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe launcher.py
```

Без открытия окон:

```powershell
.\.venv\Scripts\python.exe launcher.py --headless --port 8765 --data-dir .test-output/preview
```

## Проверки и сборка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
.\.venv\Scripts\python.exe tests/benchmark_search.py
.\.venv\Scripts\python.exe -m pip install pyinstaller==6.22.3
.\build.ps1
.\.venv\Scripts\python.exe tests/smoke_exe.py
```

Тесты используют имитацию Gemini, не отправляют файлы Google и не расходуют квоту. Измерение benchmark показывает локальные накладные расходы, количество вызовов и параллелизм; это не прогноз задержки настоящего Gemini. Проверка EXE запускает собранную программу, загружает PDF по HTTP и проверяет сохранение после перезапуска.

Если основной EXE открыт, можно собрать отдельный файл: `./build.ps1 -ExecutableName Torman-1.2.2`. Он появится в `dist/Torman-1.2.2.exe`; архив `dist/Torman-Windows.zip` будет содержать исправленную версию под обычным именем `Torman.exe`. Для проверки этого файла: `./.venv/Scripts/python.exe tests/smoke_exe.py dist/Torman-1.2.2.exe`.

## Данные и безопасность

Данные: `%LOCALAPPDATA%\Torman`. Исходный PDF, подготовка и кеш остаются после выхода. Последние 20 подборов содержат снимки результатов. API-ключ защищается Windows DPAPI или остаётся только до закрытия программы. Для разработки поддерживается переменная `GEMINI_API_KEY`.

Сервер слушает только 127.0.0.1. Запись в API защищена Host, Origin и специальным заголовком. Ключ не возвращается браузеру и не включается в архив. Исходные тексты экранируются при выводе в HTML, экспорт CSV защищён от формул. Подготовка и новые запросы передают пользовательские данные в Google Gemini; об этом указано в интерфейсе.

## Gemini API

По умолчанию `gemini-3.8-flash`; модель меняется в настройках. Используются [нативный ввод PDF](https://ai.google.dev/gemini-api/docs/generate-content/document-processing), [структурированные ответы](https://ai.google.dev/gemini-api/docs/generate-content/structured-output) и [настройка thinking](https://ai.google.dev/gemini-api/docs/generate-content/thinking). Более лёгкая [Gemini 3.5 Flash-Lite](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) доступна в списке моделей.

Проверка подключения отправляет только короткий текст без PDF и JSON-схемы каталога. Ошибки API показывают HTTP-код, статус и очищенное от ключа сообщение Google. HTTP 400 больше не маскируется общей рекомендацией уменьшить PDF. Совместимый формат схемы повторяется только при явном отказе Google от конкретного параметра; неверный ключ, недоступная модель и ограничения аккаунта не вызывают смену модели или настроек.

Реальное подключение проверяется кнопкой в программе после ввода своего ключа. Релиз без сертификата издателя: Windows может показать уведомление при запуске.
